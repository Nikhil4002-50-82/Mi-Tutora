# Rechecking the Audit: The "Alias Drift" Fallacy

## The Problem Encountered
While auditing the codebase for the "Database Integrity & Groups" issues flagged in the original PDF audit (AUD-004, AUD-005, AUD-006, AUD-013), we discovered a critical discrepancy between the documentation and the actual codebase.

Previous documentation (specifically `11-08-2026.md`) claimed that these group integrity and alias mismatch errors were fixed. However, upon deep inspection of the data lifecycle, we found that the previous developer's fixes were dangerously incomplete.

The previous fixes were superficial "find-and-replace" patches:
1. **Broken Cleanup Queries:** They renamed `groupId` to `groupDocId` inside `GroupManager.tsx`, but completely failed to update the cleanup query in `student/page.tsx`. This caused the dashboard to search for `groupId` when attempting to delete old tuition requests, permanently breaking the cleanup process and leaving ghost records floating in the database.
2. **Destructive Synchronizer:** In `groupUtils.ts`, instead of enforcing the modern schema, they chained legacy aliases (`groupData.studentDocIds || groupData.studentIds`). If a legacy record was missing these fields, the helper immediately assumed the group was empty and executed destructive `deleteDoc` commands, silently wiping out valid user data.
3. **State Desync:** They added database writes in `DemoForm.tsx` to fix orphaned students, but failed to update the local React memory (`groupPreferences`), which remained keyed by temporary UI strings (e.g., `indv_123`).

In short, the underlying architectural drift and database corruption paths were still fully active.

## How We Fixed It (15-08-2026)
Today, we eradicated the alias drift permanently by unifying the database contract and removing dangerous side-effects.

1. **Fixed Orphaned Requests in Dashboard (`student/page.tsx`):**
   Updated the cleanup query to strictly use the canonical field (`where('groupDocId', '==', reqData.id)`). Old tuition requests are now perfectly discovered and safely deleted when group assignments change.

2. **Removed Destructive Logic (`groupUtils.ts`):**
   - Removed the legacy `|| groupData.studentIds` fallback to strictly enforce the `studentDocIds` contract.
   - Entirely deleted the block of code that was aggressively auto-deleting groups based on missing arrays. Deletions are now strictly controlled by explicit user actions in the dashboard, safeguarding all group data.

3. **Validation:**
   Executed `npm run build` which compiled successfully (0 errors), proving that our surgical backend fixes did not compromise any UI design or component types.

The application now adheres to a single unified contract for groups (`groupDocId` and `studentDocIds`) without any risk of legacy aliases destroying data.
