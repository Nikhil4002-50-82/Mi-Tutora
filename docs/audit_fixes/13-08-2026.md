# Audit Fixes - 13-08-2026

This document tracks the audit tasks and fixes implemented on August 13, 2026.

## Section: Code quality and maintainability

### Task 1: Dependency/import surface does not match implementation - AUD-047

**Issue Description:**
The `package.json` file contained over a dozen heavyweight dependencies (Material UI, over 20 Radix UI components, Recharts, Axios, etc.) that were installed but completely unused in the source code. Additionally, there were several "ghost imports" (like `axios` and unused constants like `groupIds` and `logo`) lingering in various dashboard files. This created significant "dependency bloat," which increased install times, artificially inflated the vulnerability/audit surface (triggering false-positive CVEs), and created linting noise.

**How We Fixed It:**
- **Dependency Pruning:** We ran a precise `npm uninstall` to completely strip out all unused packages, including `@mui/material`, the unused `@radix-ui/*` suite, `recharts`, `axios`, `canvas-confetti`, and duplicate drag-and-drop engines, while carefully preserving active dependencies like `@hello-pangea/dnd`.
- **Import Cleanup:** We safely deleted all unused `axios` imports, the `logo` constant, and the `groupIds` constant from their respective files. 
- **Verification:** We successfully verified the application's structural integrity by running `npx tsc --noEmit` and `npm run build`.

**How We Fixed It:**

### Task 3: Hard-coded and dead concepts

**Issue Description:**
The auditor highlighted the presence of "Magic Values" (such as hard-coded 18% tax rates, ₹1000 withdrawal limits, and pending request bounds) and "Dead Concepts / Legacy States" (hard-coded status strings and references to dead database collections like `tutor_requests`).

**How We Fixed It:**
- **Magic Values (Work in Progress):** The hard-coded business rules (tax rates, fallback prices) were intentionally ignored for this audit task, as the Payment and Referral architectures are actively being developed and these are intentional placeholders.
- **Centralizing Statuses:** We extracted the massive, repetitive inline string arrays defining application statuses (`['pending', 'negotiating', ...]`) from `student/page.tsx` and `teacher/page.tsx` and centralized them into exported constants inside a new `web/src/utils/constants.ts` file. 
- **Pruning Dead Collections:** The `schema_report.md` confirmed that the `tutor_requests` and `direct_requests` collections no longer exist in the Firebase architecture. We surgically removed the defunct account-deletion loops that were attempting to query and delete from these phantom collections.
- **Verification:** Verified via `npx tsc --noEmit`.

### Task 4: God components and duplicated domain logic - Phase 1

**Issue Description:**
The dashboards (`student/page.tsx` and `teacher/page.tsx`) were flagged as massive "God Components" (3,000+ lines) that aggressively used the `any` keyword to bypass TypeScript. This allowed severe "field drift" (e.g., mixing up `paymentHistory` with `subsequentPayments`, or `groupId` with `groupDocId`) which passed compilation but broke at runtime. 

**How We Fixed It (Phase 1):**
- **Strict Domain Models:** Created `web/src/types/models.ts` containing perfectly typed interfaces (`Application`, `Group`, `Student`, `Tutor`, `User`) matching the exact Firestore schema in `schema_report.md`.
- **Surgical Type Replacement:** Automatically scanned and replaced all instances of `(app: any)`, `(group: any)`, etc., inside iterations in the dashboards with the strict types.
- **Surfacing Drift:** Running `tsc --noEmit` immediately surfaced dozens of hidden field-drift errors (like querying `tutor.languages` instead of `tutor.languagesTaught`). The `any` bypasses are completely eliminated, paving the way for Phase 2 (Extracting the business logic into services).
