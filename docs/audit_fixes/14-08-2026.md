# Audit Fixes - 14-08-2026

This document tracks the audit tasks and fixes implemented on August 14, 2026.

## Section: Configuration and deployment

### Task 1: Clean Database Truncation & Cascading Deletions
- **Goal:** Wipe out orphaned data and ensure future account deletions are 100% clean.
- **Actions:**
  1. Built and executed `db_analyzer/truncate.cjs` using Firebase Admin to truncate `users`, `tutors`, `students`, `parents`, `groups`, `applications`, `tuition_requests`, `referrals`, and `notifications`.
  2. Updated `student/page.tsx` and `teacher/page.tsx` account deletion flows to implement comprehensive cascading deletes for `groups` and `referrals`.
  3. Hardened notification deletion logic to securely check BOTH `userId` and `role`, ensuring dual-role accounts (e.g. Tutor + Parent) do not inadvertently delete their cross-profile notifications.
  4. Fully stripped out legacy `parentId` fallback checks in favor of strict `parentDocId` usage across students and groups.
- **Verification:** Verified empty database via `analyze.js` and confirmed structural integrity via `npx tsc --noEmit`.

### Task 2: Fix UI-Driven Group ID Leakage
- **Goal:** Prevent temporary frontend DOM keys (e.g., `group_1786...`) from leaking into the database as primary keys.
- **Actions:**
  1. Audited the `Manage Groups` flow and discovered `GroupManager.tsx` was generating `group_` IDs for UI buckets, which `executeGroupSave` blindly saved as absolute Firebase primary keys, risking global data collisions.
  2. Implemented a secure "ID Resolution" layer inside the `onSave` event of `GroupManager` in `student/page.tsx`.
  3. The layer intercepts `saveData`, securely generates cryptographically random 20-character auto-IDs via `doc(collection(db, 'groups')).id`, and hot-swaps the UI keys in memory *before* the database save logic executes.
- **Verification:** Ran `npx tsc --noEmit` and confirmed clean ID propagation through the existing complex React state queues.
