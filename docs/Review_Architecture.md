# Review System Architecture

## Overview
This document outlines the optimal, secure architecture for the Student-to-Teacher Review System. Parents will be able to review teachers they have successfully hired. The system enforces strict access control, prevents duplicate reviews, and efficiently aggregates data for fast frontend rendering.

## 1. Database Schema

### New Collection: `reviews`
We use a separate `reviews` collection to store each review independently. This avoids bloating the `applications` or `tutors` documents and allows for easy paginated queries in the future.

**Document ID:** Auto-generated by Firestore
**Schema:**
```typescript
{
  tutorDocId: string;       // ID of the teacher being reviewed
  parentDocId: string;      // ID of the parent writing the review
  applicationId: string;    // ID of the specific hiring instance (Group-Teacher pairing)
  rating: number;           // Integer 1 to 5
  comment: string;          // Optional text feedback
  createdAt: number;        // Timestamp
}
```

### Modified Collection: `tutors`
To ensure the "New Tuition" list loads instantly, we aggregate the review data directly onto the teacher's profile document. This eliminates the need to query the `reviews` collection when browsing teachers.

**New/Updated Fields:**
```typescript
{
  rating: number;           // The calculated average rating (1.0 to 5.0)
  reviewCount: number;      // Total number of reviews received
}
```

## 2. Security & Data Flow

To prevent malicious users from bypassing the frontend and spoofing fake 5-star reviews or manipulating average calculations, **all writes are restricted to a secure backend API**.

### Firestore Rules
```javascript
match /reviews/{reviewId} {
  allow read: if true; 
  allow write: if false; // Only the Backend API can create/update reviews
}
```

### The API Route: `/api/submit-review`
1. **Validation:** Checks if a review with the given `applicationId` already exists.
2. **Authorization:** Verifies the `applicationId` exists and its `status` is `tuition_started` (active hiring).
3. **Database Write:** Uses `firebase-admin` (which bypasses Firestore Rules) in a secure Batch Write to:
   - Create the new document in the `reviews` collection.
   - Increment `tutor.reviewCount` and mathematically update `tutor.rating`.

## 3. Frontend UI

### "My Teachers" Tab (Student Portal)
- Iterates over `data.upcomingClasses` (hired teachers).
- Displays a **Review Teacher** button next to the "View Details" button for each class.
- Uses a `ReviewModal` component featuring interactive stars (1-5) and an optional text area.
- Disables the button if a review has already been submitted for that specific `applicationId`.

### "New Tuition" Tab (Teacher Discovery)
- Seamlessly maps over the `tutors` collection.
- Renders `tutor.rating` (stars) and `tutor.reviewCount` directly on the teacher cards, utilizing the pre-calculated aggregate fields.
